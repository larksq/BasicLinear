## Integrated acceptance sequence

`P-T18` starts the local runtime and verifies automatic provisioning of exactly one owner profile and internal workspace/team context, plans one project and two milestones, creates multiple issues through global and contextual keyboard paths, assigns supported properties and relations, comments, groups and filters a dense list, saves a personal view, opens detail, changes fields, returns to retained list context, verifies progress and activity, archives/restores one issue, refreshes, and confirms committed state. It also proves login, workspace/team/member administration, switching, sharing, role, and non-owner assignee controls are absent. It then hands the dataset to recovery checks. Any facilitator intervention, critical error, local-security breach, unsupported control, or lost state fails the sequence.

## Threshold deferrals

CT-4 must produce the seeded-scale p75 budget and per-screen screenshot budgets. CT-2 must produce the Linear task-time baseline. Until those tasks complete, acceptance criteria define method and protected boundaries but do not invent numbers. O-002 remains immutable and `baseline_needed`.
