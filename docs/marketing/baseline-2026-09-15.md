## 代码核查与产品边界

- `apps/web/package.json` 没有 `@vercel/analytics` 依赖。
- 检索 `apps/web/src`、`apps/web/hosted.html` 未找到 GA/Firebase Analytics 的初始化、`logEvent`、`gtag`、`sendBeacon` 或常见 PV/UTM 埋点。Firebase 依赖存在不代表 Analytics 已接入。
- `apps/hosted-service/src/operations-telemetry.ts` 等运维遥测不能替代访客和按钮事件。
- 根 README 仍主要描述本地 v0.1；Online 登录、协作和 MCP 已有实现与部署记录。营销资料须区分两种部署形态。
- `docs/operations/creem-billing-runbook.md` 的 2026-09-14 记录显示：生产首客付费激活仍有阻塞；已验证的 2 个 Verification Pro 席位是测试豁免，不能记为付费客户或自然获客。
- `.vercel/project.json` 当前链接到 development。后续统计配置和部署必须显式核对生产项目，避免把开发统计当作生产统计。

## 结论与补齐顺序

1. 当前只有基础设施请求基线；**未知不填零，316 次请求不等于 316 位用户**。
2. 先补页面访问、CTA 点击、首次建工作区、首次有效工作、返访事件；通过去重和内部流量过滤验收后定义 T0。
3. T0 后连续七个完整日作为首个可用获客基线；历史 PV/点击不追溯编造。期间任何人工测试均标记排除。
4. [404 来源调查](404-investigation-2026-09-15.md)已对账全部 79 次请求：15 次指向缺失的标准资源；其余 64 次指向不存在的路径。独立 bot 分类中，伪装浏览器 46 次、扫描器 18 次。不能由 25% 路由占比推断 25% 用户流失。

本次完成只读核查与计划编写，没有启用分析服务、修改埋点、部署或发布营销内容。
